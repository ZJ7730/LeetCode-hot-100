# 背包题目分类对比

## 对比题目

```text
416. 分割等和子集
494. 目标和
279. 完全平方数
322. 零钱兑换
```

这四道题覆盖背包问题中最常见的三种目标：

```text
416：能不能凑出来       -> 0-1 背包可行性
494：一共有几种凑法     -> 0-1 背包方案数
279：最少需要几个平方数  -> 完全背包最小值
322：最少需要几枚硬币    -> 完全背包最小值
```

---

## 一、分类总览

### 按物品使用次数分类

```text
                         背包问题
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
          0-1 背包                    完全背包
      每个物品最多一次              每种物品无限次
              │                           │
       ┌──────┴──────┐             ┌──────┴──────┐
       ▼             ▼             ▼             ▼
   416 可行性     494 方案数     279 最少数量   322 最少数量
```

### 核心对比表

| 对比项 | 416 分割等和子集 | 494 目标和 | 279 完全平方数 | 322 零钱兑换 |
| --- | --- | --- | --- | --- |
| 背包类型 | 0-1 背包 | 0-1 背包 | 完全背包 | 完全背包 |
| 物品 | 数组元素 | 数组元素 | `1、4、9……` | `coins` |
| 使用次数 | 每个元素一次 | 每个元素一次 | 每个平方数无限次 | 每种硬币无限次 |
| 背包容量 | `sum/2` | `(sum+target)/2` | `n` | `amount` |
| 问题目标 | 能否凑出 | 方案数量 | 最少数量 | 最少数量 |
| `dp[j]` | 最大可达和或是否可达 | 凑出 `j` 的方案数 | 凑出 `j` 的最少平方数数 | 凑出 `j` 的最少硬币数 |
| `dp[0]` | `0` 或 `true` | `1` | `0` | `0` |
| 其他状态 | `0` 或 `false` | `0` | 无穷大 | 无穷大 |
| 状态合并 | `max` 或逻辑或 | 加法 | `min` | `min` |
| 容量方向 | 倒序 | 倒序 | 正序 | 正序 |
| 最终结果 | 能否恰好装满 | 返回方案数 | 返回最少数量 | 不可达返回 `-1` |

## 二、先判断是 0-1 还是完全背包

### 0-1 背包：H_416、H_494

数组中的每个下标只能处理一次：

```text
H_416：一个元素只能进入其中一个子集
H_494：一个元素只能添加一个正号或负号
```

所以容量必须倒序：

```java
for (int num : nums) {
    for (int j = target; j >= num; j--) {
        // 更新 dp[j]
    }
}
```

倒序保证计算 `dp[j]` 时，`dp[j-num]` 还是处理当前元素之前的旧状态，当前元素最多使用一次。

### 完全背包：H_279、H_322

每种物品都可以反复使用：

```text
H_279：同一个平方数可以重复选择，例如 12=4+4+4
H_322：同一种硬币可以重复选择，例如 10=5+5
```

所以容量必须正序：

```java
for (物品 item) {
    for (int j = item; j <= target; j++) {
        // 更新 dp[j]
    }
}
```

正序使 `dp[j]` 可以使用本轮刚更新的 `dp[j-item]`，从而重复选择当前物品。

### 遍历方向图解

```text
0-1 背包倒序：
大容量 <---------------- 小容量
先更新大容量，避免读取本轮刚更新的小容量状态

完全背包正序：
小容量 ----------------> 大容量
后面的容量可以读取本轮刚更新的小容量状态
```

## 三、再判断题目问什么

### 问“能不能”：H_416

使用布尔值或最大可达和：

```text
布尔写法：dp[j] = dp[j] || dp[j-num]
整数写法：dp[j] = max(dp[j], dp[j-num] + num)
```

### 问“有几种”：H_494

不同选择方案需要累加：

```text
dp[j] += dp[j-num]
```

### 问“最少几个”：H_279、H_322

原方案和加入当前物品的新方案取最小值：

```text
dp[j] = min(dp[j], dp[j-item] + 1)
```

### 状态合并总结

```text
问能不能：逻辑或
问有几种：加法
问最少几个：Math.min
问最大价值：Math.max
```

## 四、H_416 分割等和子集

### 问题转换

```text
数组能否分成两个和相等的子集
                  ↓
能否选择一些元素，使元素和等于 sum/2
```

如果数组总和为奇数，无法平均分成两个整数和，直接返回 `false`。

### 当前整数 DP 思路

```text
dp[j]：容量为 j 时能够凑出的最大子集和
```

转移：

```java
dp[j] = Math.max(dp[j], dp[j - nums[i]] + nums[i]);
```

最终：

```java
return dp[target] == target;
```

### 当前题解代码

```java
class Solution {
    public boolean canPartition(int[] nums) {
        int target = 0;
        for (int i = 0; i < nums.length; i++) {
            target += nums[i];
        }
        if (target % 2 != 0) {
            return false;
        }
        target = target / 2;

        int[] dp = new int[target + 1];

        for (int i = 0; i < dp.length; i++) {
            dp[i] = 0;
        }

        for (int i = 0; i < nums.length; i++) {
            for (int j = target; j >= nums[i]; j--) {
                dp[j] = Math.max(dp[j], dp[j - nums[i]] + nums[i]);
            }
        }

        return dp[target] == target;
    }
}
```

### 布尔 DP 模板

```java
boolean[] dp = new boolean[target + 1];
dp[0] = true;

for (int num : nums) {
    for (int j = target; j >= num; j--) {
        dp[j] = dp[j] || dp[j - num];
    }
}

return dp[target];
```

一句话：

> 每个元素只能使用一次，倒序更新；只判断能否凑出，所以使用 `max` 或逻辑或。

## 五、H_494 目标和

### 问题转换

设添加正号的元素和为 `P`，添加负号的元素和为 `N`：

```text
P-N = target
P+N = sum
```

两式相加：

```text
P = (sum+target)/2
```

原问题转换成：从数组中选择一些元素，使它们的和等于 `(sum+target)/2`，求方案数量。

### 状态定义

```text
dp[j]：使用已经处理过的元素，凑出和 j 的方案数量
```

初始化：

```text
dp[0] = 1
```

空集合是凑出 `0` 的一种方案，也是方案计数的起点。

转移：

```java
dp[j] += dp[j - nums[i]];
```

### 当前题解代码

```java
class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        int sum = 0;
        for (int i = 0; i < nums.length; i++) {
            sum += nums[i];
        }
        if (Math.abs(target) > sum) {
            return 0;
        }
        if ((target + sum) % 2 == 1) {
            return 0;
        }

        int bagSize = (target + sum) / 2;

        int[] dp = new int[bagSize + 1];
        dp[0] = 1;

        for (int i = 0; i < nums.length; i++) {
            for (int j = bagSize; j >= nums[i]; j--) {
                dp[j] += dp[j - nums[i]];
            }
        }

        return dp[bagSize];
    }
}
```

特殊点：数字 `0` 会使已有方案数翻倍，因为 `+0` 和 `-0` 是两种不同符号方案。

一句话：

> 先通过正负集合方程转换背包容量，每个元素只能使用一次所以倒序；题目求方案数，所以使用加法累加。

## 六、H_279 完全平方数

### 问题转换

```text
平方数 1、4、9……  -> 可以无限使用的物品
目标数字 n         -> 背包容量
目标               -> 恰好凑出 n 的最少物品数
```

### 状态定义

```text
dp[j]：凑出整数 j 所需的最少完全平方数数量
```

初始化：

```text
dp[0] = 0
其他位置 = 无穷大
```

转移：

```java
dp[j] = Math.min(dp[j], dp[j - i * i] + 1);
```

容量正序，使平方数可以重复使用：

```text
dp[0] --加4--> dp[4] --再加4--> dp[8] --再加4--> dp[12]
```

### 当前题解代码

```java
class Solution {
    public int numSquares(int n) {
        int[] dp = new int[n + 1];
        dp[0] = 0;
        for (int i = 1; i <= n; i++) {
            dp[i] = Integer.MAX_VALUE;
        }

        for (int i = 1; i * i <= n; i++) {
            for (int j = i * i; j <= n; j++) {
                dp[j] = Math.min(dp[j], dp[j - i * i] + 1);
            }
        }

        return dp[n];
    }
}
```

为什么不需要判断前置状态是否可达？

```text
平方数集合一定包含1，任何正整数都可以由若干个1组成。
处理完平方数1后，所有 dp[j] 都已经可达。
```

一句话：

> 平方数可以无限使用，所以是完全背包正序更新；题目求最少数量，所以使用 `Math.min`。

## 七、H_322 零钱兑换

### 问题转换

```text
硬币 coins[i]      -> 可以无限使用的物品
目标金额 amount     -> 背包容量
目标                -> 恰好凑出 amount 的最少物品数
```

### 状态定义

```text
dp[j]：凑出金额 j 所需的最少硬币数量
```

初始化：

```text
dp[0] = 0
其他位置 = 无穷大
```

转移：

```java
dp[j] = Math.min(dp[j], dp[j - coins[i]] + 1);
```

### 当前题解代码

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];
        dp[0] = 0;
        for (int i = 1; i <= amount; i++) {
            dp[i] = Integer.MAX_VALUE;
        }

        for (int i = 0; i < coins.length; i++) {
            for (int j = coins[i]; j <= amount; j++) {
                if (dp[j - coins[i]] != Integer.MAX_VALUE) {
                    dp[j] = Math.min(dp[j], dp[j - coins[i]] + 1);
                }
            }
        }
        return dp[amount] == Integer.MAX_VALUE ? -1 : dp[amount];
    }
}
```

为什么需要判断前置状态是否可达？

```text
coins 不一定包含1，某些金额可能无法凑出。
Integer.MAX_VALUE + 1 会溢出成负数，所以不能直接转移。
```

一句话：

> 硬币可以无限使用，所以完全背包正序更新；题目求最少数量，因此使用 `Math.min`，最终不可达返回 `-1`。

## 八、H_279 与 H_322 深度对比

两道题的算法骨架几乎完全相同：

```text
dp[0] = 0
其他位置 = 无穷大
物品外层
容量正序
dp[j] = min(dp[j], dp[j-item] + 1)
```

区别只在物品来源和可达性：

| 对比项 | 279 完全平方数 | 322 零钱兑换 |
| --- | --- | --- |
| 物品来源 | 自动生成 `i*i` | 题目给出 `coins[i]` |
| 是否包含 `1` | 一定包含平方数 `1` | 不一定包含硬币 `1` |
| 是否一定可达 | 一定可达 | 可能不可达 |
| 前置状态判断 | 可以省略 | 使用最大值时必须判断 |
| 最终返回 | 直接返回 `dp[n]` | 无穷大时返回 `-1` |

例如目标为 `3`：

```text
H_279：1+1+1，一定能凑出
H_322，coins=[2]：无法凑出，返回-1
```

## 九、H_416 与 H_494 深度对比

两道题都是 0-1 背包：

```text
物品是数组元素
每个下标只能使用一次
容量必须倒序
```

区别在问题目标：

| 对比项 | 416 分割等和子集 | 494 目标和 |
| --- | --- | --- |
| 数学转换 | `sum/2` | `(sum+target)/2` |
| 目标 | 判断是否存在 | 统计全部方案 |
| 状态类型 | 最大值或 boolean | 方案数量 int |
| 初始化 | `0` 或 `dp[0]=true` | `dp[0]=1` |
| 合并方式 | `max` 或逻辑或 | 加法 |

```text
416 问“至少有没有一种”：只需要保留真假
494 问“总共有多少种”：必须累加所有方案
```

## 十、四题初始化对比

初始化不是固定模板，必须由 `dp[j]` 的含义决定。

### H_416 可行性

```text
boolean dp：dp[0]=true
含义：什么都不选可以凑出0
```

或者：

```text
int dp：全部初始化为0
含义：还没有选择元素时，最大可达和为0
```

### H_494 方案数

```text
dp[0]=1
含义：什么都不选是凑出0的一种方案
```

### H_279、H_322 最少数量

```text
dp[0]=0
含义：凑出0需要0个物品

其他位置=无穷大
含义：暂时无法凑出
```

统一记忆：

```text
dp[0]=true：空集合能够凑出0
dp[0]=1：   空集合是凑出0的一种方案
dp[0]=0：   凑出0需要0个物品
```

## 十一、四题状态转移对比

```java
// H_416：能否凑出
dp[j] = dp[j] || dp[j - num];

// H_494：有多少种凑法
dp[j] += dp[j - num];

// H_279：最少几个平方数
dp[j] = Math.min(dp[j], dp[j - square] + 1);

// H_322：最少几枚硬币
dp[j] = Math.min(dp[j], dp[j - coin] + 1);
```

从统一结构理解：

```text
新 dp[j]
=
合并（不选择当前物品的旧状态，选择当前物品的前置状态）
```

合并方式取决于题目：

```text
可行性：逻辑或
方案数：加法
最少数量：Math.min
最大价值：Math.max
```

### 背包状态转移的统一结构

所有一维背包转移都可以先理解成两个选择：

```text
不选择当前物品：旧 dp[j]
选择当前物品：  从 dp[j-weight] 扩展而来
```

统一写成：

```text
dp[j] = merge(
    dp[j],                         // 不选择当前物品
    extend(dp[j-weight], item)     // 选择当前物品
)
```

其中：

```text
merge：题目要求如何合并不同选择
extend：选择当前物品后，状态增加什么贡献
```

题目问什么决定 `merge`：

```text
问能不能：merge = 逻辑或
问有几种：merge = 加法
问最大值：merge = Math.max
问最小值：merge = Math.min
```

当前物品贡献什么决定 `extend`：

```text
只判断可行性：不增加数值，只读取 dp[j-weight]
统计方案数：  当前选择对应已有的每一种方案，不额外加一
统计物品数：  dp[j-weight] + 1
统计总价值：  dp[j-weight] + value
统计总代价：  dp[j-weight] + cost
```

### 常见模式总表

| 问题模式 | `dp[j]` 的含义 | 初始化 | 选择当前物品 | 合并方式 | 典型公式 |
| --- | --- | --- | --- | --- | --- |
| 可行性 | 能否恰好凑出 `j` | `dp[0]=true` | `dp[j-weight]` | 逻辑或 | `dp[j] = dp[j] || dp[j-weight]` |
| 方案数量 | 恰好凑出 `j` 的方案数 | `dp[0]=1` | `dp[j-weight]` 种方案 | 加法 | `dp[j] += dp[j-weight]` |
| 最大价值 | 容量 `j` 下的最大价值 | 通常全为 `0` | `dp[j-weight]+value` | `Math.max` | `dp[j] = max(dp[j],dp[j-weight]+value)` |
| 最少物品数 | 恰好凑出 `j` 的最少数量 | `dp[0]=0`，其他为无穷大 | `dp[j-weight]+1` | `Math.min` | `dp[j] = min(dp[j],dp[j-weight]+1)` |
| 最小代价 | 恰好达到状态 `j` 的最小代价 | `dp[0]=0`，其他为无穷大 | `dp[j-weight]+cost` | `Math.min` | `dp[j] = min(dp[j],dp[j-weight]+cost)` |

### 模式一：可行性为什么使用逻辑或

可行性问题只关心“是否至少存在一种方案”。

```text
不选择当前物品能够凑出 j
             或者
选择当前物品能够凑出 j
```

只要其中一个条件成立，结果就是 `true`：

```java
dp[j] = dp[j] || dp[j - weight];
```

典型题：H_416。

```text
旧 dp[j] 为 true：不选当前元素也能凑出 j
dp[j-weight] 为 true：在它的方案后加入当前元素可以凑出 j
```

这里不需要计算大小，也不需要累计方案数，因为题目只问“有没有”。

### 模式二：方案数为什么使用加法

方案数问题需要统计全部选择方法。

凑出 `j` 的方案分成两类：

```text
不选择当前物品的方案数：dp[j]
选择当前物品的方案数：  dp[j-weight]
```

两类方案互不重复，所以相加：

```java
dp[j] = dp[j] + dp[j - weight];
```

简写为：

```java
dp[j] += dp[j - weight];
```

典型题：H_494。

注意这里不是：

```java
dp[j] = dp[j - weight] + 1;
```

`dp[j-weight]` 本身表示若干种方案。加入当前物品后，这些方案分别产生一条新方案，所以新增方案数量仍然是 `dp[j-weight]`，不是只增加 `1`。

例如：

```text
dp[j-weight] = 5
```

表示凑出 `j-weight` 已经有五种选择方法。在每一种方法中加入当前物品，就会得到五种凑出 `j` 的新方法，因此：

```text
新增方案数 = 5，而不是 1
```

### 模式三：最少数量为什么使用 `Math.min` 和 `+1`

最少数量问题需要在所有可行方案中选择物品数量最少的方案。

```text
不选择当前物品：dp[j]
选择当前物品：  dp[j-weight] + 1
```

`+1` 表示当前新选择了一个物品：

```java
dp[j] = Math.min(dp[j], dp[j - weight] + 1);
```

典型题：H_279、H_322。

例如当前硬币为 `5`，计算金额 `11`：

```text
原来的 dp[11]：不用当前这枚5元硬币时的最少数量
dp[6]+1：       先凑出6元，再增加一枚5元硬币
```

两种方案比较大小，保留硬币数量更少的一种。

最少数量模式必须把非起点状态初始化为无穷大：

```text
dp[0] = 0
dp[1...target] = infinity
```

如果默认初始化为 `0`：

```text
min(0, 新方案) 永远是0
```

状态将无法正确更新。

### 模式四：最大价值为什么使用 `Math.max`

最大价值问题需要比较“不选择”和“选择”当前物品哪一种收益更高：

```java
dp[j] = Math.max(dp[j], dp[j - weight] + value);
```

其中：

```text
dp[j]：不选择当前物品的最大价值
dp[j-weight]+value：选择当前物品后的价值
```

H_416 的整数写法是最大价值模式的特殊形式：

```text
weight = nums[i]
value = nums[i]
```

所以：

```java
dp[j] = Math.max(dp[j], dp[j - nums[i]] + nums[i]);
```

最后通过 `dp[target]==target` 判断背包能否恰好装满。

### 公式中的加法分别代表什么

不同公式虽然都有 `+`，含义并不相同：

```java
// 方案数合并：把两类互不重复的方案数量相加
dp[j] += dp[j - weight];

// 物品数量贡献：选择当前物品后，数量增加一个
dp[j - weight] + 1;

// 物品价值贡献：选择当前物品后，总价值增加 value
dp[j - weight] + value;

// 选择当前数组元素后，可达子集和增加 num
dp[j - num] + num;
```

所以看到加法时要问：

```text
是在合并两类方案数量？
还是在已有状态上增加当前物品的贡献？
```

### 公式中的减法代表什么

背包公式中常见：

```text
j - weight
j - coin
j - square
```

这里的减法不是“答案相减”，而是在寻找：

> 放入当前物品之前，背包剩余容量对应的前置状态。

图解：

```text
目标容量 j
┌────────────────────────────────┐
│ 前置容量 j-weight │ 当前物品 weight │
└────────────────────────────────┘
```

因此：

```text
dp[j-weight]：放入当前物品之前的状态
```

另外，H_416 和 H_494 中的数学减法属于题目转换，而不是 DP 状态合并：

```text
H_416：剩余子集和 = sum-target
H_494：P-N=target，P+N=sum
```

这四道标准背包题的状态合并通常不会使用：

```java
dp[j] -= dp[j - weight];
```

方案之间需要累计时用加法；选择最优方案时用 `min` 或 `max`；只判断存在性时用逻辑或。

### “遍历方向”和“合并方式”是两个独立问题

不要把正序、倒序与 `min`、`max`、加法绑定在一起。

```text
物品能使用几次 -> 决定容量方向
题目问什么     -> 决定状态合并方式
```

第一条判断轴：

```text
每个物品最多一次 -> 0-1背包 -> 容量倒序
每种物品无限次   -> 完全背包 -> 容量正序
```

第二条判断轴：

```text
问能不能   -> 逻辑或
问有几种   -> 加法
问最大值   -> Math.max
问最小值   -> Math.min
```

例如：

```text
H_494：0-1背包 + 方案数  -> 倒序 + 加法
H_322：完全背包 + 最小值 -> 正序 + Math.min
```

### 方案数模式还要判断组合与排列

如果是完全背包方案数问题，还需要判断是否区分物品顺序。

求组合数，不区分顺序：

```java
for (int item : items) {
    for (int j = item; j <= target; j++) {
        dp[j] += dp[j - item];
    }
}
```

例如 `1+2` 和 `2+1` 只算一种，物品放在外层。

求排列数，区分顺序：

```java
for (int j = 1; j <= target; j++) {
    for (int item : items) {
        if (j >= item) {
            dp[j] += dp[j - item];
        }
    }
}
```

例如 `1+2` 和 `2+1` 算两种，背包容量放在外层。

H_494 是 0-1 背包方案数，每个数组下标最多使用一次，所以仍然采用物品外层、容量倒序。

## 十三、面试速记

### 四题一句话

```text
416：凑 sum/2，0-1背包可行性，容量倒序。
494：凑 (sum+target)/2，0-1背包方案数，容量倒序。
279：平方数无限使用，完全背包最少数量，容量正序。
322：硬币无限使用，完全背包最少数量，容量正序，不可达返回-1。
```

### 最核心对比

```text
物品只能使用一次：倒序       -> 416、494
物品可以无限次使用：正序     -> 279、322

问能不能：逻辑或             -> 416
问有几种：加法               -> 494
问最少几个：Math.min         -> 279、322
```

### 最终记忆

> 先判断物品能使用几次，确定容量正序或倒序；再判断题目问能不能、有几种还是最少几个，确定状态类型、初始化和合并方式。
